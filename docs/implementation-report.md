## Pages improved

- Homepage: restored the existing FAQ experience and FAQ structured data.
- Services: corrected AI automation and analytics journeys to use their dedicated landing pages.
- Our work and project cards: strengthened verified Agile Digital Technologies attribution and current-client disclaimers.
- Free website review: made the visitor's primary concern or goal explicit and required.
- All service routes: navigation now treats AI automation and analytics as service pages.
- Sitemap and robots endpoints: corrected date integrity and admin exclusion.

No route was removed or renamed. No package price, testimonial, founder identity, result or certification was invented.

## SEO changes

- Preserved unique page metadata, canonicals, dynamic article metadata and existing structured-data utilities.
- Added the homepage FAQPage graph alongside the visible FAQ.
- Removed artificial sitemap dates for static and portfolio routes.
- Preserved article `lastModified` only when a real published or updated date exists.
- Corrected internal linking to the two existing specialist service pages.
- Added a maintainable keyword and internal-link map.

## Accessibility and UX changes

- The homepage now exposes buyer questions in an accessible native disclosure interface.
- The review form presents a clearer required field for the primary concern or goal.
- Active service navigation now reflects all dedicated service routes.
- Existing reduced-motion behaviour, focus treatment, semantic comparison table, live form status and labelled controls were retained.

## Trust strategy

The approved portfolio system remains gated by verification, permission, publication status and public assets. Public disclosures now name Agile Digital Technologies and describe it as a separate business under shared ownership. Unsupported outcomes, dates and technologies remain omitted.

## Performance and security

- No new runtime dependency or animation library was introduced.
- Server-rendered content and framework image optimisation remain in use.
- Lead submissions continue to use server-side Zod validation, protocol-restricted URLs, a honeypot, timing checks, rate limiting and generic storage errors.
- The in-memory rate limiter is suitable as a lightweight defence but is not globally durable across server instances.
